# 测试策略

## 单元测试（`tests/core.test.mjs`）

覆盖 `core.js` 的纯逻辑：路径端点、放塔扣钱与占位、金钱不足、升级到满级与出售返还、开波条件、符卡条件与冷却、时停冻结、同 seed 确定性重放、波次数量与 Boss。

## 平衡护栏（`tests/balance.test.mjs`）

调用 `scripts/sim.mjs` 的脚本化策略打完十波，断言：混合阵容赢；不建塔两波内输；只建两座不升级的塔输；不放符卡输；单一角色要么输，要么剩余残机少于混合阵容。bot 比真人笨，护栏只保证数值关系，不代表人玩的难度。

## 浏览器 smoke（`scripts/smoke.py`，手动）

Playwright 起本地服务器，走真实 UI 放塔、开波、放三张符卡、跳到 Boss 波，截图到 `shots/`，并收集控制台错误。不进 CI，因为要装浏览器。截图需要人或 agent 看一遍。

## 手机完整流程（`scripts/audit.py`，手动）

844×390 触屏视口：标题页 → 触屏摆塔 → 弹窗 → 切出页面自动暂停 → 打完十波（确认 Boss 曲接管）→ 结算页 → 再来一次（确认状态重置）。同时检查 HUD 按钮等高、无页面错误，截图 `shots/audit_*.png` 需要看一遍。

## 性能（`scripts/perf.py`，手动）

4× CPU 降速的 Chromium 跑满屏 Boss 波，报告主线程忙碌占比。`--mobile` 模拟触屏（启用 30 fps 上限）。当前基线约 16%；明显回升说明加了逐帧的昂贵绘制。只测 CPU，不含 GPU 合成。

## 只能人判断的

好不好玩、画风是否统一、音乐像不像 ZUN、手机上的手感。
